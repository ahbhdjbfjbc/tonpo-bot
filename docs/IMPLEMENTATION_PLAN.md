# خطة تنفيذ TONPO Bot ودمج MetaDocker

## القرار المعتمد

سيتم **إصلاح المشروع الحالي تدريجيًا**، لا إعادة كتابته. سيبقى `TRADING_DRY_RUN=true` طوال التطوير والاختبارات. لن تُستخدم حسابات حقيقية ولن تُرسل أوامر حقيقية.

## المراحل

1. **خط الأساس:** جرد الكود، تدفق الإشارة، قاعدة البيانات، الاختبارات، الأسرار، والاعتماديات الخارجية.
2. **تثبيت بيئة البناء:** توحيد Python 3.12 وPostgreSQL 16، حل تعارضات التطوير، وتشغيل CI.
3. **تأمين البيانات:** مراجعة الحقول السرية، منع التسريب في السجلات، وتحديد خطة تدوير مفاتيح دون كسر البيانات المشفرة.
4. **عقد محرك MT5:** إضافة interface مستقلة ومحول MetaDocker mocked أولًا، دون ادعاء اتصال فعلي.
5. **التوجيه الدائم:** نقل علاقة المستخدم/حساب MT5/محرك الخدمة من القواميس المحلية إلى سجل دائم قبل التشغيل متعدد المستخدمين.
6. **التنفيذ والتسوية:** تمييز `order`, `deal`, `position`، وإضافة حالات `UNKNOWN/RECONCILIATION_REQUIRED` ومنع إعادة المحاولة العمياء.
7. **Webhook والمخاطر:** تقوية التوقيع، replay/idempotency، مواصفات الرمز، وحساب الحجم fail-closed.
8. **اختبارات Demo:** تُنفذ فقط بعد توفير MetaDocker وحسابي MT5 تجريبيين، وتبقى BLOCKED حتى ذلك الحين.

## المرحلة الحالية

تم تنفيذ جزء من المرحلة 2 في Pull Request رقم 1:

- Python 3.12 في Docker و`pyproject.toml` و`.python-version`.
- PostgreSQL 16 في Compose.
- توحيد اسم قاعدة البيانات `tonpo_bot` والمستخدم `tonpo`.
- CI لـ compileall وpytest وcoverage.
- إصلاح تعارض `pylint==3.3.0` مع `isort` باستخدام `isort==5.13.2`.
- إنشاء `engine_instances` وmigration `023_add_engine_instances` لربط دائم لكل مستخدم/حساب.
- إضافة `MetaDockerConnectionAdapter` و`MetaDockerExecutionProvider` مع اختبارات mocked.
- إضافة API آمن لربط/عرض/تعطيل المحرك دون عرض API key.
- جعل guest assistant إرشاديًا فقط، مع رفض tokens غير الصالحة.

## ما بقي قبل Demo

- تشغيل migration على PostgreSQL فعلي واختبار rollback حيث يكون آمنًا.
- توفير MetaDocker `v1.0.1` على شبكة خاصة وحسابي MT5 Demo منفصلين.
- تنفيذ provisioning منفصل محدود الصلاحيات، ثم اختبار reconciliation والعزل الفعلي.
- إضافة اختبارات webhook المتزامنة واختبارات الضغط.

## بوابات منع الإطلاق

لن يُسمح بالتداول الحقيقي إذا فشل اختبار أمان أو عزل مستخدمين، أو لم تتوفر مواصفات الرمز، أو لم يمكن تحديد حالة الأمر، أو أمكن تكرار الصفقة بعد timeout، أو بقي سر مكشوف، أو فشلت migrations/الاختبارات الأساسية.

## ما لا يجوز فعله

- عدم تغيير `TRADING_DRY_RUN` إلى `false`.
- عدم اختراع endpoints أو response fields غير موثقة.
- عدم تمرير MT5 password أو API key في URL أو السجلات.
- عدم اعتبار mock أو HTTP 200 إثباتًا لتنفيذ صفقة.
- عدم تشغيل MetaDocker بمنافذ عامة أو إعطائه Docker socket.

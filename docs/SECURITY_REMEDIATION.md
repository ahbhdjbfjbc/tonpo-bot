# Security Remediation

## الحالة الحالية

لم تُطبع قيم `.env` أو مفاتيح API أو كلمات مرور في هذا الفحص. جرى التعامل مع أسماء المتغيرات فقط. بقي `TRADING_DRY_RUN=true` ولم يُستخدم حساب حي.

## نقاط تحتاج إصلاحًا أو تحققًا

1. `User` ما زال يحتوي أعمدة legacy مثل `mt5_password` و`metaapi_token`؛ يجب التحقق من البيانات المنشورة فعليًا قبل حذفها أو تغيير مفتاح التشفير.
2. `gateway_api_key` يجب أن يبقى مشفرًا/مرجعًا إلى secret store، ولا يجوز وضعه في logs أو URL.
3. يجب فحص Git history والنسخ الاحتياطية قبل إزالة الملفات الحساسة، ثم تدوير أي سر مكشوف عبر مالك الخدمة.
4. MetaDocker يجب أن يبقى على loopback/private network، مع API key قوي و`BRIDGE_READ_ONLY=1` في البداية.
5. لا Docker socket أو root privileges لتطبيق الويب.
6. إضافة اختبارات تمنع تسرب request bodies وheaders والأخطاء السرية.

## خطة تدوير المفتاح

لا يُغيّر `ENCRYPTION_KEY` عشوائيًا. أولًا تُحدد البيانات المشفرة والنسخة الحالية، ثم يُضاف دعم قراءة المفتاح القديم وكتابة الجديد، وتُرحّل الصفوف تدريجيًا في بيئة قابلة للاستعادة، وبعد تحقق النسخ الاحتياطي يُلغى القديم. لم تُنفذ هذه العملية.
